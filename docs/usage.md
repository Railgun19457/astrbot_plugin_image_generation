# 使用说明

## 命令

| 命令                                                                  | 说明                                                                                                                                       |
| :-------------------------------------------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------------- |
| `/生图 <预设/人设...> [额外提示词] [数量]` 或 `/生图 <提示词> [数量]` | 生成图片。默认从开头连续匹配预设/人设名称；开启“提示词正文匹配”后才扫描正文。末尾单独数字表示生成数量；消息、引用消息、@ 用户和人设参考图会作为参考图。引用消息与合并转发卡片只取其中的文字并入提示词，不取其中图片；只写 `/生图` 不写文字也可直接使用这些文字。 |
| `/生图任务`                                                           | 查看当前会话正在进行的生图任务，并显示编号。                                                                                               |
| `/生图任务 <编号或任务ID>`                                            | 查看任务详情。编号仅匹配当前列表中的进行中任务；完整任务 ID 可查看仍保留记录的已结束任务。                                                  |
| `/生图取消 <编号或任务ID>`                                            | 取消当前会话中仍在排队、运行或取消中的生图任务。                                                                                           |
| `/生图模型`                                                           | 查看可用模型和当前模型。                                                                                                                   |
| `/生图模型 <序号>`                                                    | 切换到指定序号的模型，并立即刷新运行时配置。                                                                                               |
| `/预设`                                                               | 查看所有预设和人设。                                                                                                                       |
| `/预设 添加 <预设名:预设内容>`                                        | 添加或覆盖预设，支持英文冒号 `:` 和中文冒号 `：`。                                                                                         |
| `/预设 删除 <预设名>`                                                 | 删除预设。                                                                                                                                 |

## 使用示例

基础生图：

```text
/生图 一只在森林里野餐的兔子
```

使用预设：

```text
/预设 添加 赛博朋克:cyberpunk style, neon lights, futuristic city
/生图 赛博朋克 猫
```

使用人设：

```text
/生图 看板娘 在咖啡店读书
```

组合多个预设/人设：

```text
/生图 手办化 看板娘 夜景 微笑
/生图 画一张看板娘手办化夜景
```

一次生成多张：

```text
/生图 手办化 看板娘 夜景 微笑 3
```

本次指定宽高比和分辨率：

```text
/生图 一只站在山顶的猫，比例 16:9，分辨率 2K
/生图 猫 宽高比为 9:16
/生图 猫 使用 4:3 画幅，使用 4K 分辨率
/生图 猫 16:9 2K 3
/生图 电影 猫 2K 16:9 3
```

开启 OpenAI 供应商的「自动识别 GIF」后，可用空格分隔的 `gif` 参数请求动图，大小写均可。

```text
/生图 小猫摇尾巴 gif 3
/生图 GIF 手办化 小猫摇尾巴
```

图生图：

```text
发送或引用一张图片后输入：/生图 变成动漫风格
/生图 变成像素风 @用户A
```

切换模型：

```text
/生图模型
/生图模型 2
```

查看或取消任务：

```text
/生图任务
/生图任务 1
/生图任务 1a2b3c4d
/生图取消 1
/生图取消 1a2b3c4d
```

## 尺寸参数识别

`/生图` 会提取“比例、宽高比、画幅、分辨率”附近明确写出的参数，兼容中文冒号、空格和 `k/K` 大小写，也支持末尾连续、独立的比例与分辨率简写（顺序不限）。数量仍放在最后，例如 `16:9 2K 3` 表示比例 `16:9`、分辨率 `2K`、生成数量 `3`；`16 : 9` 的末尾 `9` 不会被当成数量。正文中没有关键词的孤立数字和尺寸不参与提取，例如“猫在 16:9 屏幕前”。“高分辨率2K”“大画幅16:9”等粘连词会留在提示词中；末尾无法识别的简写（如 `8K`）也不当参数。

- 比例支持：`1:1`、`2:3`、`3:2`、`3:4`、`4:3`、`4:5`、`5:4`、`9:16`、`16:9`、`21:9`；分辨率支持：`1K`、`1.5K`、`2K`、`4K`。关键词后也可填写“不指定”，表示本次不发送该参数。
- 每个参数分别遵循“本次明确指定 > 高级预设 > 全局默认值”。只指定比例时，分辨率仍可沿用预设；不会修改全局配置，也不会重新解析预设正文中的尺寸描述。
- 已识别的参数短语会从提示词中清除；未指定参数时沿用原有行为。值无效时会回复支持的选项，重复相同值允许，不同值冲突时提示修改；这些错误不会提交生图任务或扣除额度。
- 参数识别仅用于 `/生图`，LLM 工具和插件公共 API 继续使用已有的结构化参数。

任务记录保留请求的比例和分辨率；调试日志可按任务 ID 查看请求值、适配器忽略情况，以及发往接口的 JSON 或表单尺寸字段。查看请求体/表单尺寸需启用“调试请求日志”。这些字段表示接口请求参数，不是对成图像素的验证：例如 GPT Image 的 `16:9` 仍按现有规则映射为 `1536x1024`，OpenAI Images 不发送插件的 `2K` 分辨率参数；不支持尺寸的适配器仍按原有能力处理。

## 引用与转发文字

```text
引用一条消息后输入：/生图 把这些对话画成漫画分镜
引用一条消息后只输入：/生图
转发一条聊天记录卡片后输入：/生图 根据上面的记录画插画
```

取用规则：

- 引用消息的文本、合并转发卡片里第一层消息的文本都会作为素材并入提示词，放在自己写的要求前面；两者同时存在时都会取用。
- 只取一层：卡片内再嵌的转发不会深入，避免递归拉取。
- 只取文字，不取图片：引用或卡片里的图片不会作为参考图，图片仍按原有参考图规则（当前消息、引用消息、@ 用户、人设）收集。
- 卡片里的图片、视频、文件占位符（`[Image]`、`[Video]`、`[File:…]`）会被清除，不会混进提示词；重复的行只保留一次（带昵称的行按整行比较）。
- 素材最多取 1000 字符，超出部分会被截断，避免长记录撑爆提示词。
- 只写 `/生图` 不写文字也可以：此时直接用引用或转发的文字作为提示词；读不到文字才会提示补充。
- 拿不到卡片标题和预览文字（如「xxx的聊天记录」那行）。入站消息里这类卡片只带一个 ID，标题不在其中。
- 只有 `/生图` 指令会取用这些文字；LLM 工具会自行查看引用内容并组织提示词，不经过这里。
- 解析失败（卡片过期、协议端不支持 `get_forward_msg`）时只在控制台输出日志，聊天里不会提示；没有文字可用时会提示补充提示词。

## 任务体系

- `/生图` 指令、LLM 生图工具和公共 API 共用统一任务体系：任务提交后会生成 `task_id`，进入排队/运行/完成/失败/取消状态。- 完整任务级并发由“最大并发完整生图任务数”控制，超过后任务保持排队，不会开始参考图转换或模型调用。
- 模型接口请求级并发仍由“最大并发生图请求数”控制，多图任务会在请求并发限制内发起多个子请求，完成一个后继续补发剩余请求。
- 插件会在收集参考图和预约额度前预检查队列容量；队列满时会直接拒绝新任务，避免不必要的下载和图片处理。
- `requested_count` 表示模型接口子请求数量，不保证等于最终图片数量；`result_count` 表示实际保存的结果图片数量。部分适配器单次子请求可能返回多张图片。
- 生成多张图片时会按“单条消息最多图片数”自动分批发送，结果信息附加在最后一批。
- `/生图任务` 只展示当前会话正在进行的任务，并为列表项添加编号；可通过 `/生图任务 <编号或任务ID>` 查看详情，通过 `/生图取消 <编号或任务ID>` 取消仍在排队或运行中的任务。
- 取消排队任务后会立即更新用户可见状态并释放占用；底层队列项由 worker 后续惰性跳过，不会开始参考图转换或模型调用。
- 历史任务元数据可持久化到插件数据目录，插件重载后最近的已结束任务仍可查询；重启前未完成的任务会恢复为已取消，不会继续执行。
- 默认会把生成的图片持久化到插件数据目录的 `generated_images/`（可在“任务持久化”中关闭或设置数量上限）；关闭持久化或超出上限后，`result_paths` 可能指向已被清理的临时文件，调用方需要容忍路径不存在。

## WebUI 页面

- 页面右上角可切换生图模型，与 `/生图模型 <序号>` 等价：切换后立即持久化并刷新运行时配置，后续指令、LLM 工具和页面提交都使用新模型。
- 「生成」页的参考图、宽高比和分辨率按该页「模型」下拉框所选模型的能力自动启用或禁用；模型未出现在能力表中（或尚未选择模型）时回退到右上角当前模型的判断结果。
- 「生成」页上传参考图后会显示缩略图预览：可点击查看大图，也可单张移除，下方显示已选数量。
- 右上角的刷新会重新拉取插件状态并刷新当前页面数据；各标签页不再单独提供刷新按钮。
- 「任务」页左侧任务列表用彩色圆点表示状态，右侧是任务详情；详情里的提示词和错误信息默认折叠，错误默认只显示 1 行，点击“查看完整错误”/“展开完整提示词”可查看全文，子任务错误同样支持展开。
- 「图库」页支持按模型、时间范围、数量和关键字筛选，并提供上一页/下一页翻页；「隐藏已清理」默认开启，会隐藏文件已被清理的图片，关闭后可看到这些条目（缩略图位置显示“文件已清理”，下载按钮不可用）。
- 任务与图库中的错误信息会保留完整的模型接口返回内容（最多 2000 字符），便于直接复制错误原因排查；任务失败时日志会额外输出一行「错误详情」给出同样的完整错误。
- 注意：本次调整只对**之后新产生**的任务生效。此前历史记录中保存的错误在写入时就已被截断到 300 字符（子任务 200 字符），文件里只留下 `...(N chars)` 标记，无法恢复。
